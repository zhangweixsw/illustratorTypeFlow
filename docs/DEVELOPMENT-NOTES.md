# 我为什么做了一个 Illustrator 输入法“管家”

做设计的时候，有一种小麻烦特别磨人：它不至于让软件崩掉，但一天能打断你好几十次。

在 Illustrator 里改图层名、输中文，需要中文输入法；鼠标一回到画布，想按 `V` 切选择工具，输入法还开着，快捷键就可能变成字母输入。再去改宽高、坐标和字号，又希望它老老实实保持英文。手动按一次中英切换不难，难的是每隔几分钟都要想起这件事。

这个小工具，就是从这点烦人的事开始的。

## 一开始以为很简单

最早的想法很直接：看看当前窗口是不是 Illustrator，再看看光标是不是在输入框里。是输入框就开中文，不是就关掉。

真做起来，马上发现 Illustrator 里的“输入框”不是一种东西。

图层重命名当然要中文，宽高参数框却要英文；第三方插件里的文字框和网页面板，有时对 Windows 暴露出来的控件信息几乎一样。更麻烦的是画布文字。你在画板上点进一段文字时，系统不一定能像普通文本框那样明确告诉外部程序“这里正在编辑文字”。

如果简单粗暴地见到输入框就开中文，参数输入会变得很难用；如果只认最标准的文本控件，画布文字和不少插件又会漏掉。

## 先把问题拆成两层

后来我把判断分成了两层。

第一层处理 Illustrator 界面里比较标准的控件。程序通过 Windows 的辅助功能接口读取当前焦点，结合控件类型、名称、层级和一些常见特征，判断它更像文字框还是数字参数框。图层名、画板名和普通文字输入框优先走中文；尺寸、坐标、字号、透明度、角度这类位置优先走英文。

第二层专门处理画布文字。理想方案是一个很小的 Illustrator 原生插件，只负责问 Illustrator：“现在有没有文字插入点或文字选区？”然后把这个真假状态发给托盘程序。插件不碰文档，也不负责切输入法，职责尽量收窄。

Adobe 的 Illustrator SDK 不能跟项目一起随便分发，所以免费交付版先保证托盘程序单独也能用。没有原生插件时，程序会根据文字工具、鼠标点击、退出编辑和工具切换这些动作做校正。它不如插件状态那么绝对，但常用的点文字、双击文字、按 `Esc` 或 `Ctrl+Enter` 退出，基本能覆盖。

## 没走“模拟按键”这条捷径

市面上不少自动切输入法的小工具，会模拟 `Shift`、`Ctrl+Space` 或 `Win+Space`。这样写起来快，但副作用也明显：用户改了快捷键会失效，不同输入法行为不完全一样，按键还可能刚好撞上 Illustrator 的操作。

这个项目没有模拟键盘，而是直接请求当前输入法切换打开或关闭状态。这样不需要猜用户装的是微软拼音还是微信输入法，也不会偷偷往正在编辑的文档里塞一个按键事件。

这里有个很重要的取舍：程序只管“当前中文输入法开还是关”，不替用户挑选具体输入法。你喜欢用哪个，还是由你自己决定。

## 误判不可能只靠硬编码解决

Illustrator 本身就有很多面板，再加上第三方插件，控件名字和实现方式五花八门。靠我在代码里不断追加名单，早晚会变成一团很难维护的规则。

所以托盘菜单里留了三个看起来不太“自动”的选项：把当前输入框设为文字框、设为参数框、清除规则。

这不是偷懒，反而是我觉得比较实际的做法。自动判断覆盖大多数情况，少数只出现在某台电脑、某个插件里的特殊控件，让使用者点一次就记住。规则保存在本机，不需要把控件信息上传到服务器。

## 状态切换最怕抖

焦点变化不是一下一下整齐发生的。点进一个面板时，系统可能在很短时间里连续报告窗口、容器、文本框等几个焦点。如果每次都立刻切输入法，图标和输入状态会来回跳。

项目里做了一个很短的防抖，并把“当前观察到的状态”和“最后真正执行的状态”分开。只有判断稳定且目标状态确实变化时，才调用输入法接口。切出 Illustrator 时，还会恢复进入前的输入状态，尽量不影响浏览器、聊天软件和其他工作。

这部分代码看着不如界面显眼，却是实际用起来顺不顺手的关键。

## 测试不是只看“能不能切”

自动化测试主要盯状态决策：画布文字是否比普通焦点判断优先，数字字段会不会被中文命名误导，用户手动规则能不能覆盖默认分类，插件消息丢失时是否能安全退回。

手工测试更接近日常使用。我会在画布文字和选择工具之间连续切很多次，再去试图层重命名、宽高、透明度、第三方插件输入框，以及 `Alt+Tab` 切走和退出程序。因为这类工具真正的问题，往往不是第一次能不能工作，而是用半小时之后会不会突然卡在错误状态。

## 现在这个版本是什么状态

v1.0.0 是一个 Windows x64 免费版，主程序做成自包含单文件，电脑不用预装 .NET。安装只写入当前用户目录和当前用户的开机启动项，不需要管理员权限。

它现在已经能解决我最开始遇到的那类麻烦：写中文时少按一次切换键，回到画布时快捷键能直接用。它不是一个“大而全”的 Illustrator 插件，更像是放在托盘里、平时不打扰人的小管家。

后面如果继续做，我更想花时间补真实场景，而不是堆设置项。哪些输入框容易误判、哪些输入法组合有特殊行为、画布文字在不同 Illustrator 小版本里有什么差异，这些来自实际使用的反馈，比再加十个开关更有价值。

做这个工具的过程也让我重新确认了一件事：效率工具不一定要替人完成多复杂的工作。能把一天里反复出现的那一下停顿拿掉，就已经有用了。
